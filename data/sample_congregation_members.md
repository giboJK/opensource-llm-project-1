# 가상 교인 목록 (STEP 4~7 실험용 입력 문서)

> 전부 가상의 이름/상황입니다(실제 인물과 무관, `scripts/generate_sample_congregation.py`로 합성
> 생성, seed=42). 전체 데이터는 `data/congregation_300_3y.json`(300명/3년)를 참고하세요.
> 규모 비교용으로 `data/congregation_500_5y.json`, `data/congregation_1000_10y.json`도 있습니다.

## 구성

- **앞의 15명**: 손으로 만든 인물 — `data/questions.json`의 질문 10개가 이름으로 직접 참조합니다.
- **그다음 17명**: 위 15명 중 일부의 **배우자/자녀/부모**를 새로 만든 인물입니다.
- **나머지**: 1인 가구/부부/자녀가 있는 가정/3대 가정을 무작위 비율로 섞어 채운 인물.
- **ID**: 영문 대소문자와 숫자를 섞은 6자리입니다. 순번이 드러나지 않게 하려는 것이며,
  인원수(300/500/1000)가 달라져도 같은 사람은 같은 ID를 갖습니다.

## 각 인물이 가진 정보

| 필드 | 내용 |
|---|---|
| 기본 정보 | 나이, 성별, 신앙 연차, 최근 8주 출석, 건강 상태, 최근 경조사, 비고 |
| `family` / `family_note` | 이 데이터셋 안의 가족관계(배우자/자녀/아버지/어머니/할아버지/할머니/손자/손녀), 없으면 사유 |
| `prayer_requests` | 기도제목 목록. **인원당 평균 6개(최소 0, 최대 15)**, 각 항목은 내용/등록일/상태(진행 중·응답됨·계속 기도 중) |
| `visitation_records` | 최근 3년간의 심방 기록. `last_visitation_date`를 마지막 기록으로 삼아 **평균 약 3개월(90일)에 한 번** 꼴로 역산해서 생성 (정보가 없는 사람은 빈 목록) |
| `community_history` | 최근 3개년(각 연도)의 소속 공동체. 연도별로 **0~2개**(무소속 가능), 나이대에 맞춰 배정 |

### 정보 부족 교인 (전체의 약 10%)

실제 교회 명부에서 담당자 입력이 빠진 성도를 재현한 구간입니다. `--unknown-ratio`로 조절하며
권장 범위는 8~12%입니다. 300명 기준 30명이 여기 해당합니다.

| 단계 | 내용 | 인원(300명 기준) |
|---|---|---|
| 전면 미기재 | 출석까지 포함해 판단 근거가 전부 "정보 없음" | 25명 |
| 기본만 있음 | 출석 기록만 남고 건강/경조사/비고/심방/기도제목/소속이 모두 비어 있음 | 5명 |

누가 여기 속하는지는 데이터에 따로 적지 않습니다. 실제 교회 DB에 "이 사람 기록이 비었다"는
표시가 없는 것과 같습니다. 채점할 때 명단이 필요하면 기도제목/심방기록/소속이력이 모두 빈 사람을
그대로 추리면 됩니다.

```python
cohort = [m["id"] for m in members
          if not m["prayer_requests"] and not m["visitation_records"] and not m["community_history"]]
```

### 앞뒤가 맞도록 건 제약

- 소속 이력과 기도제목 등록일은 신앙 연차를 넘지 않습니다. 지난주에 처음 온 사람에게
  3년치 소속 이력이 붙지 않습니다.
- 기도제목은 나이와 성별에 맞는 주제만 붙습니다. 29세에게 "군 복무 중인 자녀",
  8세에게 "취업/이직"이 붙지 않습니다.
- 비고란에는 그 사람에 대한 사실만 적습니다. 데이터 설명("정보 부족 사례")이나 판단 지시
  ("자녀는 보호자 기준으로 판단 필요")는 넣지 않습니다. 그런 문구가 있으면 모델이 스스로
  판단하는 대신 명부에 적힌 답을 따라 읽게 됩니다.
- JSON 최상위에는 `communities`와 `members`만 있습니다. 생성 조건이나 정보 부족 교인 명단처럼
  실제 교회 DB에 없을 항목은 파일에 넣지 않습니다.

## 프롬프트에 붙여넣는 방법

300명 전체를 요약형으로 넣어도 약 3,900줄(1.4만 단어)이라 대부분의 모델에게 여전히 깁니다.
필요한 범위만 뽑아 쓰세요.

```powershell
# 앞 30명만, 심방 기록은 요약으로 (기본 실험 추천)
uv run scripts/format_congregation_prompt.py --limit 30 > data/_congregation_prompt_block.txt

# 특정 인물만, 심방 기록 전체 나열
uv run scripts/format_congregation_prompt.py --ids OhbVrp,bfnoGM,IAoCLr,Z3aWZk,9Wvgfy --full-history

# 전체 300명 (아주 긴 Context 실험용)
uv run scripts/format_congregation_prompt.py > data/_congregation_prompt_block_full.txt
```

이 텍스트를 `01_ollama_chat.py`/`02_cloud_chat.py`의 `QUESTION` 앞부분(문서)으로 붙여넣고,
뒤에 실제 질문(STEP 5의 질문 10개 중 하나)을 이어 붙이면 됩니다.

> 참고: 후보 모델의 Context Length가 이 분량을 감당하는지가 STEP 2/3에서 확인할 항목입니다.
> **두 로컬 후보에는 반드시 같은 `--limit`/`--ids`/`--full-history` 옵션을 동일하게 적용**하세요.

## 다시 생성하기 / 규모 조정하기

```powershell
uv run scripts/generate_sample_congregation.py
```

`scripts/generate_sample_congregation.py` 상단의 `TOTAL_MEMBERS`(인원 수)와
`HISTORY_YEARS`(심방/소속 이력 연수) 값을 바꾸면 규모를 조정할 수 있습니다
(손으로 만든 앞의 15명과 그 가족은 항상 유지됩니다).
