# STEP 1. 문제 정의

> 모델을 고르기 전에 "무엇을 위한 모델인지"부터 한 문장으로 정리합니다.

## 한 문장 정의

> (예시) 한국어 고객 문의에 답변하는 사내 상담 Assistant에 사용할 로컬 모델을 선정한다.

**우리 팀의 한 문장 정의:**

> 교회 심방 준비를 돕기 위해, 교인 명부를 읽고 심방 대상을 근거와 함께 추천하는 한국어 로컬 모델을 선정한다.

- **외부 전송 없음**: 교인 정보를 Cloud API로 보내지 않고 노트북에서만 실행한다.
- **근거 기반**: 답변은 입력한 명부에 있는 내용만 근거로 삼고, 정보가 부족하면 부족하다고 밝힌다.

## 서비스/사용 환경

| 질문 | 답변 |
|---|---|
| 어떤 사용자가 사용하는가? | 심방을 담당하는 교역자. 교인에게 직접 노출되지 않는다. |
| 어떤 종류의 질문/작업에 답해야 하는가? | ① 명부를 읽고 이번 주 심방 대상과 우선순위 추천 ② 특정 교인에게 어떤 방식으로 다가갈지 제안 ③ 건강·경조사 등 조건으로 대상 추리기 ④ 정보가 부족하거나 명부에 없는 사람은 지어내지 않고 확인이 필요하다고 답하기 |
| 한국어 성능이 중요한가? | 매우 중요(필수). 입력 문서·질문·답변이 모두 한국어이고, 호칭과 존댓말이 어색하면 그대로 쓰기 어렵다. |
| 데이터 보안이 중요한가? | 매우 중요(필수). 건강 상태, 경조사, 기도제목 등 민감 정보라 외부 API 전송이 불가하다. 로컬 실행이 후보 자격 조건이다. |
| 응답 속도가 중요한가? | 우선순위 낮음. 주 단위 심방 준비에 쓰므로 실시간성보다 근거의 정확성이 먼저다. 다만 질문당 전체 응답 시간은 기록해 후보 비교에 사용한다. |
| 사용 가능한 GPU/환경은 어느 정도인가? | 수업용 Windows 11 노트북 (GPU: NVIDIA GeForce RTX 5060 Laptop, VRAM: 8,151MiB ≒ 8GB, 드라이버 592.01). Ollama로 실행하며, 모델과 컨텍스트를 합쳐 약 7GB 안에서 돌아가야 한다. |

## Use Case 선택 이유

- **팀 상황과의 연결**: 심방 대상 선정은 지금도 담당자의 기억과 수기 메모에 의존해서, 오래 안 보인
  교인이나 최근 경조사를 겪은 교인이 빠지기 쉽다. 명부를 그대로 읽고 후보를 뽑아주는 도우미가 있으면
  준비 시간을 줄이면서 누락을 줄일 수 있다.
- **로컬 모델이어야 하는 이유가 분명하다**: 명부에는 건강 상태, 경조사, 기도제목처럼 외부에 올릴 수 없는
  정보가 들어 있다. "성능이 조금 낮아도 로컬이어야 한다"는 제약이 자연스럽게 성립해서, 이 과제의
  Local vs Cloud 비교 구도와 잘 맞는다.
- **모델 간 차이가 드러나는 과제다**: 긴 명부를 읽어야 하므로 Context Length, 한국어 표현, 근거 없는
  추측을 억제하는 정도에서 후보별 차이가 실제로 갈린다. STEP 5 질문 10개도 일반 4개 / 판단이 갈리는
  상황 3개 / 정보 부족 3개로 나눠 이 차이를 보도록 구성했다.
- **실험 데이터는 전부 가상이다**: `data/congregation_300_3y.json`의 300명은
  `scripts/generate_sample_congregation.py`로 합성한 가상 인물이라(seed=42), 실제 개인정보 없이
  같은 조건을 두 로컬 후보에 반복 적용할 수 있다.

## 부록. 실험용 데이터 현황 점검 (2026-09-14)

> STEP 4 준비 단계에서 입력 문서(가상 교인 명부)가 STEP 5 질문 10개의 의도에 맞게
> 구성돼 있는지 확인한 기록입니다. 전부 합성 데이터이며 실제 인물과 무관합니다.

### 현재 데이터 파일

| 파일 | 인원 | 이력 연차 | 정보 부족 | 상태 |
|---|---|---|---|---|
| `data/congregation_300_3y.json` | 300명 | 3년 | 30명(10.0%) | **기본 실험용.** 스크립트 기본 경로 |
| `data/congregation_500_5y.json` | 500명 | 5년 | 50명(10.0%) | 규모 비교용 |
| `data/congregation_1000_10y.json` | 1000명 | 10년 | 100명(10.0%) | 규모 비교용 |

생성 명령(시드 42 고정, 다시 실행해도 같은 결과):

```powershell
uv run scripts/generate_sample_congregation.py --total 300 --years 3 --out data/congregation_300_3y.json
uv run scripts/generate_sample_congregation.py --total 500 --years 5 --out data/congregation_500_5y.json
uv run scripts/generate_sample_congregation.py --total 1000 --years 10 --out data/congregation_1000_10y.json
```

데이터 파일에는 **명부만** 들어갑니다. 최상위 키는 공동체 목록(`communities`)과
교인 목록(`members`) 둘뿐입니다. 생성 조건, 정보 부족 교인 명단, 데이터 설명처럼 실제 교회 DB에
없을 항목은 저장하지 않습니다. 그 설명은 생성 스크립트의 주석과 이 문서에 있습니다.

### 한 사람이 가진 정보 (300명/3년 기준)

| 구분 | 필드 | 실측 |
|---|---|---|
| 기본 | 나이, 성별, 신앙 연차 | 0~90세(평균 36세), 미성년 96명 |
| 심방 판단 근거 | 최근 8주 출석, 건강, 경조사, 비고 | 출석 0~2주 84명 / 출석 정보없음 25명 / 건강 이슈 151명 / 경조사 146명 |
| 관계 | `family`, `family_note` | 가족 링크 568건(전부 양방향 일치), 가족 없음 33명 |
| 이력 | `prayer_requests` | 1인당 평균 5.5개(0~15), 0개인 인원 33명 |
| 이력 | `visitation_records` | 1인당 평균 7.9건, 기록 0건인 인원 116명 |
| 이력 | `community_history` | 최근 3개년, 연도별 0~2개 소속 |
| 결측 | 정보 부족 교인 | 30명(10.0%) = 전면 미기재 25명 + 출석만 있음 5명 |

`--limit 30`으로 앞 30명만 넣어도 출석 저조 8명, 건강 이슈 5명, 경조사 7명, 정보 부족 3명이
포함되어 "이번 주 심방 대상 3명" 같은 질문에 근거가 부족하지 않습니다.

### 질문 10개와의 대조 결과

의도대로 준비된 부분입니다.

- 유형 배분이 설계대로입니다. 일반 4개 / 판단이 갈리는 상황 3개 / 정보 부족 3개.
- 질문이 이름으로 부르는 11명이 모두 손으로 만든 앞의 15명 안에 있고, 필드 값도 질문 의도와 맞습니다.
  김도윤은 낙상 후 자택 요양, 노은채는 요양병원 장기 입원, 임도현은 실직에도 출석 5주,
  한소율은 지난주 부친상에 출석 6주로 "출석률만으로 판단하면 틀리는" 구도가 성립합니다.

### DB 규모별 성능 비교 계획

명부를 통째로 프롬프트에 넣는 방식은 규모 비교가 성립하지 않습니다. 요약 모드 기준 입력 길이는
아래와 같고, 300명 전체만 해도 로컬 모델 대부분의 컨텍스트를 넘습니다.

| 데이터셋 | 넣는 인원 | 글자 수 | 대략 토큰 |
|---|---|---|---|
| 300명/3년 | 30명 | 12,939 | 약 1.0만 |
| 300명/3년 | 100명 | 42,645 | 약 3.3만 |
| 300명/3년 | 300명 전체 | 129,786 | 약 10.0만 |
| 500명/5년 | 500명 전체 | 231,243 | 약 17.8만 |
| 1000명/10년 | 100명 | 54,484 | 약 4.2만 |
| 1000명/10년 | 1000명 전체 | 555,393 | 약 42.7만 |

따라서 규모 비교는 두 축으로 나눠서 봅니다.

- **축 1. 입력 길이 한계 찾기**: 같은 300명 데이터에서 넣는 인원만 30명, 100명, 300명으로 늘려가며
  같은 질문을 던지고, 어느 지점에서 근거가 흐려지는지 본다. 정답 인물을 명부 앞쪽과 뒤쪽에
  각각 두고 비교하면 긴 문서의 중간을 놓치는 현상도 확인할 수 있다.
- **축 2. 이력 깊이의 영향**: 인원을 30명으로 고정하고 3년치/5년치/10년치를 바꿔 넣는다.
  같은 30명이라도 10년치는 요약 기준 1.6만 자, 전체 이력 기준 6.1만 자로 늘어난다.

주의할 점이 있습니다.

- **`num_ctx`를 반드시 명시해야 합니다.** Ollama는 기본 컨텍스트가 작아서, 값을 주지 않으면
  앞부분이 조용히 잘린 채 답이 나옵니다. 잘렸는지는 응답의 `prompt_eval_count`로 확인합니다.
  `run_local_experiment.py`의 `GENERATION_OPTIONS`에 후보 두 모델 모두 같은 값을 넣습니다.
- ID는 영문 대소문자와 숫자를 섞은 6자리입니다. 세 데이터셋에서 같은 사람은 같은 ID를 가지므로
  `--ids`로 지정한 실험을 규모만 바꿔 그대로 반복할 수 있습니다.
- 8MB짜리 1000명 파일은 저장소에 커밋할지 팀에서 정합니다. 시드가 고정이라 명령 한 줄로 언제든
  다시 만들 수 있으므로 `.gitignore` 처리도 선택지입니다.
