# STEP 2. 모델 요구사항 정의

STEP 1의 유저 시나리오 1번(새로 부임한 목사)을 기준으로 정합니다. 사용자는 공동체를 모르는
상태에서 **공동체 요약**과 **심방 후보 2명**을 한 번에 요청합니다.

## 후보를 볼 때 확인할 정보

| 항목 | 확인할 정보 | 우리 기준 |
|---|---|---|
| Language | 한국어 지원 여부 | 필수. 입력과 답변이 모두 한국어 |
| Model Size | 수업용 노트북에서 실행 가능한 크기 | 가중치와 컨텍스트를 합쳐 VRAM 약 7GB 이하 |
| License | Commercial Use 가능 여부 | 교회 내부 업무 사용이 허용될 것 |
| Context Length | 입력 문서와 출력 길이 수용 여부 | 최소 16k. 넣는 명부 범위는 STEP 4에서 실측해 확정 |
| GPU | 실제 GPU·VRAM과 CPU/GPU 적재 상태 | RTX 5060 Laptop, VRAM 8,151MiB. 전량 GPU 적재 |
| Task | Chat / QA | 문서를 읽고 요약과 추천을 함께 답하는 QA 형태의 Chat |

## 입력 구성

프롬프트는 세 덩어리입니다. 세 후보 모두에 같은 구성을 적용합니다.

1. 사용자 정보 (부임 2주 차, 공동체 정보 없음, 주당 심방 2~3건)
2. 명부 (범위는 STEP 4에서 확정)
3. 질문

명부 분량은 아래와 같이 계산했습니다. 명부 전체는 VRAM과 시간 모두 감당되지 않으므로 넣는
범위를 정해서 씁니다.

| 명부를 넣는 범위 | 대략 토큰 |
|---|---|
| 30명 | 0.7만 |
| 100명 | 2.3만 |
| 300명 전체 | 5.9만 |
| 1000명 전체 | 23.0만 |

## 필수 통과 조건

하나라도 못 넘으면 후보에서 제외합니다.

| 조건 | 기준 | 확인 방법 |
|---|---|---|
| 수업용 노트북에서 실행 | 가중치와 컨텍스트를 합쳐 VRAM 약 7GB 이하, 전량 GPU 적재 | `ollama ps`의 SIZE와 PROCESSOR 열 확인. CPU로 넘어가면 미달 |
| License | 교회 내부 업무에 쓸 수 있을 것 | Model Card의 License 원문 확인 |
| 입력·출력 길이 수용 | Context Length 16k 이상 | Model Card 확인 후 `num_ctx` 지정, 응답의 `prompt_eval_count`가 실제 입력 토큰 수와 맞는지 확인 |
| 응답 시간 | 질문 하나당 **2분 이내**. 목표는 1분 | 전체 응답 시간 측정. 2분을 넘기면 제외 |
| 한국어 출력 | 한국어로 답하고 호칭과 존댓말이 그대로 쓸 수 있는 수준 | STEP 5 채점의 한국어 항목 |
| 요청 이행 | 요약과 심방 후보 2명을 **한 답변에 모두** 담을 것 | 둘 중 하나라도 빠지면 미달 |
| 최소 품질 | STEP 5 채점 기준으로 평균 기준점 이상 | STEP 5에서 숫자로 확정 |
| 정보 부족 대응 | 기록이 없는 교인에 대해 근거를 지어내지 않을 것 | 정보 부족 문항과 명부에 없는 인물을 묻는 문항 |

정보 부족 대응은 점수가 아니라 통과 여부로 판정합니다. 없는 사실을 지어내면 심방 대상을
잘못 고르게 되고, 다른 항목의 점수로 메울 수 없습니다.

## 선호 우선순위

필수 조건을 통과한 후보들 사이에서는 아래 순서로 봅니다.

1. **추천 근거의 정확성**: 후보로 고른 사람의 출석, 건강, 경조사가 명부 내용과 맞는가.
2. **요약의 정확성**: 인원 수, 연령 분포, 기록이 비어 있는 인원 같은 집계가 맞는가.
3. **한국어 표현**: 손보지 않고 바로 읽을 수 있는 문장인가.
4. **전체 응답 시간**: 2분 안에 들어온 후보들 사이에서는 1분에 가까운 쪽.
5. **메모리 사용량**: 같은 조건이면 VRAM을 덜 쓰는 쪽.

판정 기준입니다.

- 한국어는 유창한데 근거가 틀리는 후보는 탈락입니다.
- 요약의 숫자가 틀리는 것은 표현이 어색한 것보다 심각하게 봅니다. 두 오류는 사용자가
  알아챌 수 있는지가 다릅니다. 한국어가 어색하면 읽는 순간 바로 보이고 직접 고칠 수 있습니다.
  반면 "65세 이상 40명, 기록이 비어 있는 사람 30명" 같은 숫자는 틀려도 사용자가 알 수 없습니다.
  부임 2주 차라 공동체를 모르니 대조할 기억이 없고, 틀린 숫자를 그대로 믿고 심방 계획을
  세우게 됩니다. 사용자가 잡아낼 수 없는 오류를 더 위험하게 봅니다.
- 점수가 비슷하면 정보 부족 문항의 성적으로 가릅니다.

## 확정 시점

- 명부를 몇 명까지 넣을지는 STEP 4에서 응답 시간과 VRAM을 실측해 확정합니다.
- 질문과 품질 채점 기준은 STEP 5에서 구체화합니다. 평균 몇 점 이상 같은 숫자를 그때 확정합니다.
- 확정한 기준은 본 실험 전에 고정하고, 후보 전체에 똑같이 적용합니다. 넣는 명부 범위와
  `num_ctx`도 동일하게 맞춥니다.
