# STEP 2. 모델 요구사항 정의

## 후보를 볼 때 확인할 정보

| 항목 | 확인할 정보 | 기준 |
|---|---|---|
| Language | 한국어 지원 여부 | 필수. 입력 문서와 질문, 답변이 모두 한국어 |
| Model Size | 수업용 노트북에서 실행 가능한 크기 | 가중치와 컨텍스트를 합쳐 VRAM 약 7GB 이하 |
| License | Commercial Use 가능 여부 | 허용되는 것만 |
| Context Length | 입력 문서와 출력 길이 수용 여부 | 최소 16k. 명부 30명이 약 7천 토큰 |
| GPU | 실제 GPU·VRAM과 CPU/GPU 적재 상태 | RTX 5060 Laptop, VRAM 8,151MiB. 전량 GPU 적재 |
| Task | Chat / QA | 문서를 읽고 답하는 QA 형태의 Chat |

입력 문서 길이는 명부에서 직접 계산한 값입니다.

| 명부를 넣는 범위 | 글자 수 | 대략 토큰 |
|---|---|---|
| 30명 | 9,027 | 약 0.7만 |
| 100명 | 29,599 | 약 2.3만 |
| 300명 전체 | 88,859 | 약 6.8만 |

## 필수 통과 조건

하나라도 못 넘으면 후보에서 제외합니다.

| 조건 | 기준 | 확인 방법 |
|---|---|---|
| 수업용 노트북에서 실행 | 가중치와 컨텍스트를 합쳐 VRAM 약 7GB 이하, 전량 GPU 적재 | `ollama ps`의 SIZE와 PROCESSOR 열 확인. CPU로 넘어가면 미달 |
| License | 교회 내부 업무에 쓸 수 있을 것 | Model Card의 License 원문 확인 |
| 입력·출력 길이 수용 | Context Length 16k 이상 | Model Card 확인 후, `num_ctx`를 지정하고 응답의 `prompt_eval_count`가 실제 입력 토큰 수와 맞는지 확인 |
| 한국어 출력 | 한국어로 답하고 호칭과 존댓말이 그대로 쓸 수 있는 수준 | STEP 5 채점의 한국어 항목 |
| 최소 품질 | STEP 5 채점 기준으로 평균 기준점 이상 | STEP 5에서 숫자로 확정 |
| 정보 부족 대응 | 기록이 없는 교인에 대해 근거를 지어내지 않을 것 | 정보 부족 문항과 명부에 없는 인물을 묻는 문항 |

정보 부족 대응은 점수가 아니라 통과 여부로 판정합니다. 없는 사실을 지어내면 심방 대상을
잘못 고르게 되고, 다른 항목의 점수로 메울 수 없습니다.

## 선호 우선순위

필수 조건을 통과한 후보들 사이에서는 아래 순서로 봅니다.

1. **품질 — 근거의 정확성**: 추천한 사람의 출석, 건강, 경조사가 명부 내용과 맞는가.
2. **품질 — 한국어 표현**: 손보지 않고 바로 읽을 수 있는 문장인가.
3. **전체 응답 시간**: 질문 하나당 걸리는 시간.
4. **메모리 사용량**: 같은 조건이면 VRAM을 덜 쓰는 쪽.

판정 기준입니다.

- 품질이 높지만 느린 경우 품질을 택합니다. 다만 질문 하나에 3분을 넘기면 제외합니다.
- 한국어는 유창한데 근거가 틀리는 후보는 탈락입니다.
- 점수가 비슷하면 정보 부족 문항의 성적으로 가릅니다.

## 확정 시점

- 질문과 품질 채점 기준은 STEP 5에서 구체화합니다. 평균 몇 점 이상, 응답 시간 상한 같은 숫자를 그때 확정합니다.
- 확정한 기준은 본 실험 전에 고정하고, 두 로컬 후보에 똑같이 적용합니다. 넣는 명부 범위와 `num_ctx`도 동일하게 맞춥니다.
