# STEP 2. 모델 요구사항 정의

> STEP 1의 한 문장 정의에서 곧바로 따라 나오는 조건들입니다.
>
> "교회 심방 준비를 돕기 위해, 교인 명부를 읽고 심방 대상을 근거와 함께 추천하는
> 한국어 로컬 모델을 선정한다."

## 실행 환경 (측정값)

| 항목 | 값 |
|---|---|
| GPU | NVIDIA GeForce RTX 5060 Laptop |
| VRAM | 8,151MiB ≒ 8GB (드라이버 592.01) |
| 실행 방식 | Windows 11 + Ollama |
| 쓸 수 있는 VRAM | 약 7GB. 나머지는 윈도우 화면 출력 등이 씁니다 |

입력 문서 길이는 다음과 같이 측정했습니다. 컨텍스트 요구치는 여기서 나옵니다.

| 명부를 넣는 범위 | 글자 수 | 대략 토큰 |
|---|---|---|
| 30명, 심방 기록은 요약 (기본 실험) | 12,929 | 약 1.0만 |
| 30명, 심방 기록 전체 | 25,386 | 약 2.0만 |
| 100명, 요약 | 41,541 | 약 3.2만 |
| 300명 전체, 요약 | 124,011 | 약 9.5만 |

## 필수 통과 조건 (Must-pass)

하나라도 못 넘으면 후보에서 제외합니다.

| 조건 | 기준 | 확인 방법 |
|---|---|---|
| 로컬 실행 | 모델을 내려받아 노트북에서 실행. 추론 중 외부로 데이터가 나가지 않을 것 | `ollama pull` 후 네트워크를 끊고 응답이 나오는지 확인 |
| VRAM 안에서 동작 | 모델 가중치와 컨텍스트를 합쳐 약 7GB 이하 | `ollama ps`의 SIZE와 PROCESSOR 열 확인. CPU로 넘어가면 조건 미달 |
| Context Length | **16k 이상**. 기본 실험 입력이 약 1만 토큰이고 질문과 답변이 더 붙습니다. 규모 비교까지 하려면 32k 이상이 편합니다 | Model Card의 context length 확인 후, `num_ctx`를 지정하고 응답의 `prompt_eval_count`가 실제 입력 토큰 수와 맞는지 확인 |
| License | 교회 내부 업무에 쓸 수 있을 것. 사용 범위 제한과 재배포 조건을 원문으로 확인 | Model Card의 License 원문 |
| 한국어 출력 | 질문 10개에 한국어로 답하고, 호칭과 존댓말이 그대로 쓸 수 있는 수준일 것 | STEP 5 채점의 한국어 항목 |
| 최소 품질 | STEP 5에서 정할 채점 기준으로 평균 기준점 이상 | STEP 5에서 숫자로 확정 |
| 정보 부족 대응 | 정보가 없는 교인에 대해 근거를 지어내지 않을 것 | 정보 부족 3문항(q07, q08, q09)과 명부에 없는 인물을 묻는 q10 |

마지막 두 줄은 STEP 5에서 숫자를 확정합니다. 다만 **정보 부족 대응은 점수가 아니라 통과 여부로 봅니다.**
없는 사실을 지어내면 심방 대상을 잘못 고르게 되고, 이건 다른 항목의 점수로 메울 수 없습니다.

## 선호 우선순위 (Nice-to-have)

필수 조건을 통과한 후보들 사이에서는 아래 순서로 봅니다.

1. **근거의 정확성** — 추천한 사람의 출석, 건강, 경조사가 명부 내용과 실제로 맞는가.
2. **판단이 갈리는 상황의 처리** — 출석률만 보지 않고 실직이나 부친상 같은 정성적 사정을 함께 보는가.
3. **한국어 표현** — 교역자가 손보지 않고 바로 읽을 수 있는 문장인가.
4. **전체 응답 시간** — 질문 하나당 걸리는 시간.
5. **VRAM 여유** — 같은 조건이면 가볍게 도는 쪽.

## 결과가 엇갈릴 때

- **품질이 높지만 느린 경우, 품질을 택합니다.** 심방 준비는 주 단위 작업이라 몇십 초 차이는
  문제가 되지 않습니다. 다만 질문 하나에 3분을 넘기면 수업 중 시연이 어려우므로 그 지점을 상한으로 둡니다.
- **한국어는 유창한데 근거가 틀리는 경우, 탈락시킵니다.** 그럴듯한 문장으로 틀린 사람을 추천하는 것이
  이 Use Case에서 가장 나쁜 실패입니다.
- **점수가 비슷하면 정보 부족 문항의 성적으로 가릅니다.**

## 확정 시점

- 채점 기준의 구체적인 숫자(평균 몇 점 이상, 응답 시간 상한)는 STEP 5에서 확정합니다.
- 확정한 기준은 두 로컬 후보에 똑같이 적용합니다. 넣는 명부 범위와 `num_ctx`도 동일하게 맞춥니다.
