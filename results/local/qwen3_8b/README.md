# qwen3:8b — 중단된 실험

2026-09-17 14:32 시작, **4/20에서 중단.**

## 왜 돌렸나

STEP 6에서 두 4B 후보가 모두 미달했다. 원인이 모델 크기인지 가리려고 같은 계열의 8B를
같은 조건(10세트 × 2회, `num_ctx` 16384, `temperature` 0)으로 돌렸다.

## 왜 멈췄나

**VRAM이 부족했다.**

| 항목 | 값 |
|---|---|
| 전체 VRAM | 8,151 MiB |
| 모델이 요구한 크기 | 7,450 MiB |
| GPU에 올라간 양 | **5,995 MiB** |
| 적재 상태 | **20% CPU / 80% GPU** |

가중치 일부가 CPU로 넘어가면서 회당 **186초**가 걸렸다. 4B의 13초보다 14배 느리다.
생성 속도도 21.9 tok/s로 4B의 69.0 tok/s에 크게 못 미친다.

4건을 처리한 뒤 `ollama ps`가 `Stopping...` 상태에서 멈췄고, 59분 동안 한 건도 진행되지
않았다. 프로세스를 강제 종료해 정리했다.

## 결과 (n=4, 참고용)

| 세트 | 포함 | 제외 위반 | 시간 | 생성 속도 | 형식 |
|---|---|---|---|---|---|
| set01 #1 | 5/10 | 0 | 165.3초 | 21.7 tok/s | OK |
| set01 #2 | 5/10 | 0 | 161.5초 | 22.3 tok/s | OK |
| set02 #1 | 4/10 | 0 | 196.5초 | 22.0 tok/s | OK |
| set02 #2 | 6/10 | 0 | 221.1초 | 21.5 tok/s | OK |
| 평균 | **5.0/10** | **0.0** | **186초** | 21.9 tok/s | 4/4 OK |

워밍업 1회는 263.1초(로딩 5.39초)였다.

**4건뿐이라 통계로 쓸 수 없다.** 세트도 set01·set02 두 개만 돌았다.

## 4B와 비교 (참고)

| | qwen3 8b (n=4) | qwen3 4b (n=20) | 통과선 |
|---|---|---|---|
| 포함 | 5.0/10 | 3.8/10 | 7/10 |
| 제외 위반 | **0.0** | 1.3 | 0 |
| 형식 미달 | 0/4 | 14/20 | 0 |
| 응답 시간 | **186초** | 13.0초 | 60초 이내 |
| 적재 | **20% CPU / 80% GPU** | 100% GPU | 전량 GPU |

품질 지표는 모두 나아졌다. 제외 위반 0, 형식 미달 0은 4B에서 못 보던 값이다.
포함도 5.0으로 3.8보다 높다. 다만 통과선 7에는 못 미친다.

## 판정

**후보 자격 없음.** STEP 2의 필수 통과 조건 두 개를 어겼다.

| 조건 | 기준 | 결과 |
|---|---|---|
| 전량 GPU 적재 | VRAM 7GB 이하 | **미달** — 20%가 CPU |
| 응답 시간 | 60초 이내 | **미달** — 186초 |

품질이 좋아져도 이 두 가지로 탈락이다.

## 알게 된 것

**8GB VRAM에서 8B 모델로 50명 명부를 돌리는 것은 구조적으로 안 된다.**

`num_ctx`를 줄이면 전량 GPU에 올릴 수 있지만, 입력이 이미 10,747토큰이라 12288 이하로
내리면 **명부가 잘린다.** 잘린 명부로는 4B와 같은 조건이 아니게 되어 비교가 성립하지 않는다.

즉 이 장비에서 8B는 **조건을 지키면서 돌릴 방법이 없다.**

## 남은 한계

- 4건은 표본이 아니다. "8B가 4B보다 낫다"고 말할 수 없다
- `qwen3:4b`와 `qwen3:8b`는 `rope.freq_base`가 다르다(5,000,000 대 1,000,000). 크기만 다른
  비교가 아니다
- CPU로 넘어간 상태의 출력이 전량 GPU일 때와 같은지 확인하지 않았다
